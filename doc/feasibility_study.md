# Tap Titans 2 자동 환생(Auto-Prestige) 모바일 헬퍼 기술 검토 보고서

## 1. 개요 및 목적
- **대상 게임**: Tap Titans 2 (모바일 방치형 RPG)
- **목표 기능**: 게임 플레이 중 특정 층(Stage)에 도달하면 자동으로 환생(Prestige) 시퀀스를 수행하는 헬퍼 구축
- **핵심 요구사항**: PC 연결 없이 **스마트폰 단독으로 실행**, 이동 중(지하철, 버스 등)에도 게임 위에 띄워두고 백그라운드/오버레이 형태로 동작 가능 여부 검토

---

## 2. OS 플랫폼별 실현 가능성 (Feasibility Overview)

| OS | 실현 가능성 | 이유 및 제약 사항 |
| :--- | :---: | :--- |
| **Android** | **가능 (매우 높음)** | `AccessibilityService`(무루트 자동 터치) 및 `MediaProjection`(화면 캡처) 공식 API 제공. 플로팅 오버레이 UI 구현 가능. |
| **iOS (아이폰)** | **불가 (탈옥 제외)** | 엄격한 샌드박스 정책으로 타 앱 화면 캡처 불가, 타 앱 내 좌표 터치 주입 불가. (Switch Control 등 수동 보조 기능만 가능) |

> **결론**: 본 프로젝트는 **Android 스마트폰**을 타겟으로 개발해야 이동 중 단독 실행이 가능합니다.

---

## 3. 안드로이드 단독 구현 방식 비교 분석

스마트폰 단독으로 게임 화면을 인식하고 터치를 입력하는 방법은 크게 3가지가 있습니다.

### 방식 1. 안드로이드 전용 네이티브 앱 개발 (접근성 서비스 + 미디어 프로젝션) ⭐ [가장 추천]
- **동작 원리**:
  1. **오버레이 뷰 (Floating Overlay)**: `WindowManager(TYPE_APPLICATION_OVERLAY)`를 통해 게임 상단에 작은 컨트롤러(시작/정지, 목표 층수 입력) 표시
  2. **화면 캡처 (MediaProjection API)**: 게임 상단의 층수 영역만 3~5초 간격으로 크롭하여 캡처
  3. **층수 인식 (On-Device OCR)**: `Google ML Kit Text Recognition` 또는 경량 OCR 모델을 통해 현재 층수 텍스트 파싱
  4. **자동 터치 (AccessibilityService API)**: 무루트(Non-Root) 환경에서 `dispatchGesture()`를 사용해 소드마스터 탭 클릭 -> 환생 버튼 클릭 -> 확인 팝업 터치 수행
- **장점**:
  - **100% 모바일 단독 동작**: PC나 Wi-Fi 연결 전혀 불필요. 이동 중 완벽 동작.
  - **무루트(No-Root)**: 일반 안드로이드 폰에서 바로 설치 및 구동 가능.
  - 깔끔한 UX/UI (플로팅 버튼으로 게임 켜고 바로 헬퍼 토글 가능).
- **단점/난이도**:
  - 안드로이드 네이티브 앱(Kotlin/Java) 개발 필요.
  - 최초 실행 시 접근성 권한 및 화면 캡처 권한 허용 필요.

---

### 방식 2. Shizuku / 무선 ADB 기반 자동화 (Termux/Python 스크립트)
- **동작 원리**: 안드로이드 내부의 무선 디버깅(Wireless Debugging) 포트를 열고 `Shizuku`를 통해 `adb shell screencap`과 `adb shell input tap`을 수행.
- **장점**: 개발이 간단(파이썬 스크립트로 작성 가능).
- **단점**:
  - 폰 재부팅 시 무선 디버깅을 다시 페어링해야 함 (Wi-Fi 환경 필요할 수 있어 이동 중에 취약).
  - 일반적인 앱 형태가 아니라 터미널(Termux) 등에서 명령어를 쳐야 하므로 모바일 이동 중 사용성(UX)이 매우 떨어짐.

---

### 방식 3. 기존 서드파티 매크로 앱 활용 (Tasker + AutoInput / 스마트 오토클릭 등)
- **동작 원리**: 이미 출시된 오토클릭 앱이나 Tasker의 자동화 룰을 조합.
- **장점**: 별도 코딩 없이 빠르게 테스트 가능.
- **단점**:
  - '특정 층수 도달 시 환생'과 같은 정밀한 숫자 인식/조건 분기 처리가 매우 까다로움.
  - 화면 UI 변경이나 보스 타임아웃 등 예외 처리가 어려움.

---

## 4. 핵심 기술 구현 상세 (방식 1 기준)

### 4.1. 층수 감지 파이프라인 (OCR)
1. **타겟 영역 크롭**:
   - TT2 화면 상단 중앙/좌측에 현재 층수(`Stage 12,345`)가 위치합니다.
   - 전체 화면을 OCR 돌리면 연산량과 배터리 소모가 크므로, 층수 영역(예: 화면 상단 5~10% 높이)만 비트맵으로 크롭.
2. **온디바이스 경량 OCR**:
   - `Google ML Kit Text Recognition (v2)`: 기기 내에서 로컬로 10~30ms 만에 텍스트 추출 가능 (데이터 소모 없음).
3. **데이터 정제 (Regex)**:
   - 숫자와 쉼표 파싱: `12,345` -> `12345` 정수 변환.
   - 단위 표기 처리 (게임 설정에 따라 K, M 단위 표기가 있을 경우 환산 로직 포함).

### 4.2. 환생(Prestige) 자동 터치 시퀀스
1. `현재 층수 >= 목표 층수` 조건 만족 시 환생 절차 트리거.
2. **시퀀스 단계**:
   - Step 1: 좌측 하단 '소드마스터(Sword Master)' 탭 클릭
   - Step 2: 스크롤 다운 또는 환생(Prestige) 버튼 영역 클릭
   - Step 3: 환생 확인 모달 창에서 '환생 진행(Confirm)' 버튼 클릭
   - Step 4: 2차 확인 창 클릭 (필요 시)
   - Step 5: 로딩 애니메이션 및 1층(또는 복귀 층) 리셋 완료 대기 (약 5~10초 슬립)
   - Step 6: 헬퍼 상태를 다시 '층수 감시 모드'로 전환

### 4.3. 사용자 인터페이스 (Floating Window)
- 게임을 가리지 않는 반투명 원형 플로팅 아이콘 (Game Guardian, 통화 플로팅 버블 형태).
- 터치 시 미니 패널 열림:
  - 현재 인식된 층수 표시 (디버그용)
  - 목표 층수 입력 필드
  - 시작 / 정지 버튼

## 5. 리스크 및 고려 사항

### 5.1. 게임사 제재 (Ban / Teapot) 리스크
- **TT2의 치팅 감지 방식**:
  - TT2는 메모리 변조(치트엔진, 스피드핵)나 비정상적인 환생 속도(서버 유물 계산 검증)를 주로 감지(Teapot 상태로 분류)합니다.
  - 일반적인 화면 터치 매크로는 클라이언트 단독 터치 주입이므로 메모리 변조 탐지에 걸리지 않습니다.
- **방지 대책**:
  - **랜덤 지터(Jitter) 적용**: 고정된 좌표(x, y)를 그대로 누르지 않고, 반경 $\pm 5\sim 15\text{px}$ 내에서 랜덤하게 클릭.
  - **랜덤 딜레이(Delay)**: 클릭 간격을 고정(예: 1.000초)하지 않고 `850ms ~ 1250ms` 사이 난수 부여.

### 5.2. 해상도 및 기기 호환성
- 안드로이드 기기마다 화면 비율(16:9, 19.5:9, 20:9 등)과 펀치홀 카메라 위치가 다름.
- 절대 픽셀 좌표(`x=500, y=1000`) 대신 화면 비율 기반 상대 좌표(`x = width * 0.45, y = height * 0.85`) 또는 템플릿 매칭 적용 필요.

### 5.3. 배터리 소모 및 발열
- TT2 게임 자체가 3D 그래픽으로 배터리 소모가 있는 편입니다.
- 헬퍼가 매 프레임(60fps) 화면을 분석하면 발열이 심해지므로, **3~5초에 1회 캡처 & 층수 판별** 주기로 설정하여 CPU 점유율을 1% 미만으로 유지해야 합니다.

## 6. 결론 및 권장 개발 단계

### 최종 결론
**"안드로이드 환경이라면 이동 중 핸드폰 단독으로 동작하는 헬퍼 제작이 100% 가능하며, 기술적으로도 매우 안정적인 방식으로 구현할 수 있습니다."**

### 단계별 개발 로드맵 (추천)
1. **1단계 (기본 골격 구축)**:
   - 안드로이드 프로젝트 생성 (Kotlin)
   - 접근성 서비스(AccessibilityService) 권한 및 플로팅 오버레이 뷰(Floating Window) 구현
2. **2단계 (화면 캡처 & OCR 테스트)**:
   - MediaProjection 설정 후 게임 상단 층수 영역 크롭
   - ML Kit로 실제 층수 숫자가 오차 없이 읽히는지 확인
3. **3단계 (환생 터치 매크로 구현)**:
   - 층수 조건 도달 시 메뉴 열기 -> 환생 -> 확인 클릭 시퀀스 작성
   - 랜덤 좌표 및 딜레이 난수화 적용
4. **4단계 (사용자 편의 기능 및 안정화)**:
   - 해상도 캘리브레이션 기능 (처음 앱 켤 때 버튼 위치 미세 조정 가능하게 구성)
   - 폰 화면 꺼짐 방지(WakeLock) 옵션 추가
